# Kitchen Chaos 真人多人联机完整工程

这是在 `https://github.com/subtob/KitchenChaos` 的单机工程上补齐的房主权威联机版本，按本次提供的多人联机策划案开发。基线提交为 `2397878da4c2cca181e9698974ad10cf8fac9575`。保留原厨房、食材模型、厨师动画、音效和单机资源，实际游戏入口自动切换为多人联机流程。

**先运行，再验收：** 已通过纯 C# 玩法回归和真实 TCP 收发测试；当前制作环境没有 Unity 编辑器，因此尚未在 Unity 中完成导入、Windows 构建或画面与双开游玩的验收。不要把自动测试通过等同于已在你的电脑上验证可运行。按下文步骤进行首次运行；遇到红色编译错误时保留 Console 的第一条完整错误。

## 放到你指定的目录

1. 将压缩包完整解压到任意目录，路径不要过长。
2. 双击根目录的 `安装到指定目录.cmd`。
3. 脚本将完整代码复制到 `E:\Users\HP\Desktop\大三课程\实训\KitchenChaos-Multiplayer`。如果该目录已有内容，会新建带时间后缀的目录，避免覆盖原文件。
4. 后续使用目标目录里的工程。Unity 项目根目录是其中的 `KitchenChaos` 文件夹，里面同时有 `Assets`、`Packages`、`ProjectSettings`，不是压缩包最外层文件夹。

当前交付环境无法访问你的 Windows E 盘；这个安装脚本负责在你的电脑上完成复制。它不修改旧工程、不需要管理员权限。

## 环境与第一次打开

- 安装 Unity Hub，并在其中安装 **Unity 2022.3.62f3**。
- 同时安装 **Windows Build Support (Mono)**。首次导入需要网络下载仓库原有的 Unity 包，例如 Input System 和 URP。
- Unity Hub → Projects → Add → Add project from disk → 选择上述目标目录中的 `KitchenChaos`。
- 等待导入和脚本编译完成，Console 不应存在红色错误。
- 菜单 `Kitchen Chaos → Validate Project` 检查资源、配置和构建场景。
- 菜单 `Kitchen Chaos → Open Multiplayer Kitchen` 打开 `Assets/Scenes/GameScene.unity`，然后点击 Play。也可以从 MainMenuScene 的 PLAY 按钮进入。
- 无须拖拽新增脚本，无须安装 Mirror、Photon、Netcode 或启动额外 Python 服务。运行 GameScene 时会自动创建联机会话与界面。

`启动项目.cmd` 可在标准安装路径下直接打开编辑器。若 Unity 安装在其他盘，可直接通过 Hub 打开，或将环境变量 `UNITY_EDITOR` 设置为你的 `Unity.exe` 完整路径。

## 同一台电脑双开测试

1. 先退出编辑器 Play 模式。
2. 菜单 `Kitchen Chaos → Build Windows Multiplayer` 生成 Windows 版，位置为 `KitchenChaos\Builds\Windows\KitchenChaos.exe`。必须安装对应的 Windows 构建模块。
3. 双击根目录的 `双开测试.cmd`，启动两个窗口。也可以一个窗口用编辑器 Play，另一个用已构建的 exe，但两边必须是同一份代码和配置。
4. 第一个窗口输入昵称，端口保持 `7777`，点击“创建房间”，记下界面显示的六位房间码。
5. 第二个窗口输入不同昵称，房主地址填写 `127.0.0.1`，端口 `7777`，填写六位房间码，点击“加入房间”。
6. 两个窗口分别点击“准备”，房主点击“开始本局”。至少需要两名玩家。
7. 三秒倒计时后开始300秒对局。切换窗口时前一个窗口停止本机输入，但房间时间继续流逝。

## 两台至四台电脑联机

1. 所有电脑连接同一局域网，使用同一个 Windows 构建。分发整个 `Builds\Windows` 文件夹，不能只复制 exe。
2. 房主创建房间。大厅显示本机 IPv4；若有多个网卡，在命令提示符运行 `ipconfig`，选择实际 Wi-Fi 或以太网适配器的 IPv4 地址。
3. 其他玩家填写房主 IPv4、端口和房间码加入，不能填写自己的 IP，也不能使用 `127.0.0.1`。
4. Windows 弹出网络访问提示时，允许此程序在当前专用网络通信。检查房主入站 TCP 7777 可达；无需另开 UDP 端口。
5. 全员准备后房主开始。中途不接收新玩家；等房主在结算页返回房间后再加入。

这里采用 TCP 直连，不提供公网匹配、房间服务器或自动 NAT 穿透。异地联机需要可达的网络地址，例如同一虚拟局域网，或自行配置房主端口映射。六位房间码是房间校验标识，不能单独代替 IP 地址。

## 操作与一份菜的制作

| 按键 | 功能 |
|---|---|
| WASD 或方向键 | 移动 |
| Shift | 奔跑 |
| E | 取料、拿盘、放下、拿起、装盘、出餐或丢弃 |
| F | 在砧板前空手切菜，每刀有1秒间隔 |
| Esc | 打开本机菜单；联机时间继续走 |

面向操作台并靠近，屏幕下方会显示当前目标。按 E 后等待服务端确认；若队友抢先操作，界面会提示重新操作。

以经典牛肉堡为例：

1. 在餐盘架按 E 拿一个盘子，再到空台面按 E 放下。
2. 到面包篮按 E 取面包，到放有餐盘的台面按 E，将面包加入餐盘。
3. 到生肉饼篮取料，将肉饼放到空炉灶上；等待8秒变熟，过熟后再等待8秒会烧焦。
4. 空手从炉灶拿起熟肉饼，到餐盘台面按 E 装盘。
5. 空手拿起餐盘，走到出餐窗口按 E 提交。

蔬菜和奶酪需先放到砧板，空手按 F 四次加工后才能装盘。未加工食材、烧焦肉饼不能装盘。餐盘既可以放在台面上逐个加入食材，也可以拿在手中从台面收集已加工食材。

菜单图标下的数字表示**装盘先后顺序**；重复图标表示需要多份同一种食材。例如双番茄沙拉要求一份卷心菜丝后加入两份番茄片，需实际处理两份番茄。界面支持显示重复配料；现有3D餐盘模型同种食材只显示一个对应造型，以手持栏图标中的实际份数为准。

每局从10道内置预设食谱中随机抽取4道，同一房间菜单一致。开局四张订单覆盖这四道菜，之后每4秒检查一次订单空位，从本局菜单补一单，最多同时4单。没有单独的订单倒计时。

## 结算与可调参数

策划案未提供精确的分值和星级阈值，本实现采用以下默认参数，并不声称是原案已有的具体数值：

- 正确出餐每单加100分；误交每单扣10分并回收餐盘。
- 300秒结束时，仍在等待列表中的订单每单扣10分，总分最低为0。
- 1星起评；分数达到100、300、600、1000时依次升至2、3、4、5星。
- 出餐正确率 = 正确出餐数 ÷ 实际提交次数。未提交的超时订单单列，不计入该分母。
- 最佳出餐时间为成功订单从出现到交付的最短时间。
- 失败订单数 = 误交数 + 全局时间结束时未完成数；参与人数包含本局中途离开的玩家。

配置文件为 `KitchenChaos/Assets/Resources/MultiplayerRules.json`，包含食谱、份数、装盘顺序、速度、加工时间、评分参数。食谱用重复数组元素表达多份食材。所有客户端需使用同一份配置和场景；版本指纹不同会拒绝加入。修改配置后重新构建并分发。

## 断线与重开

- 普通玩家离开：手持物品优先移到最近的空普通台面；没有空台面则清理。炉灶和砧板上的物品继续属于台面，可由队友接手，不保留离线玩家锁。
- 剩余玩家可以继续本局。重新连接视为新加入，仅能在大厅进行，不恢复旧身份。
- 房主退出或断线：其他玩家看到连接中断提示并返回连接大厅，不迁移房主。
- 结算后房主点击“返回房间再来一局”，清空物品和订单，全员重新准备。下局重新抽取菜单。

## 常见问题

| 现象 | 处理 |
|---|---|
| Hub说不是Unity项目 | 选择包含 Assets、Packages、ProjectSettings 的内层 KitchenChaos 文件夹 |
| 一直在下载包 | 首次导入依赖网络，查看 Package Manager 错误，先修复包下载 |
| 找不到Windows构建模块 | Hub中为2022.3.62f3添加 Windows Build Support (Mono) |
| 第二个Unity编辑器打不开同一工程 | 用构建出的exe双开，或编辑器加exe，不同时用两个编辑器打开同一项目 |
| 连接超时 | 检查房主已创建房间、IP正确、同一局域网、防火墙和TCP端口 |
| 地址有多个IPv4 | 不要选虚拟机、断开的网卡或回环地址；使用实际网络适配器的IPv4 |
| 版本或配置不同 | 所有人重新获取同一个完整构建；不要只替换某一份JSON |
| 开始按钮不能点 | 至少两名玩家且每个人都准备；只有房主能开始 |
| 按E没反应 | 确认本局已开始、靠近并面向台面、手持与设备状态允许该操作 |
| F连续快速按被拒绝 | 每刀有1秒间隔，需要空手切菜 |
| 模型看似有两份但交付失败 | 以订单与手持栏图标的顺序和数量为准，肉饼必须熟、蔬菜必须切 |
| 开菜单后时间仍走 | 这是多人联机行为，只停止本机操作，不暂停队友对局 |

## 代码分工

| 部分 | 路径 | 职责 |
|---|---|---|
| 后端 | Assets/Multiplayer/Core | 房间准备、开局、权威移动与交互、归属、去重、食谱、订单、加工、计时、结算 |
| 链接与集成 | Assets/Multiplayer/Link 与 Runtime/MultiplayerSession.cs | TCP分帧、收发队列、握手、版本校验、连接身份、心跳、快照广播、生命周期 |
| 前端 | Assets/Multiplayer/Runtime/NetworkWorldView.cs 与 MultiplayerUI.cs | 角色与物品显示、输入、平滑、界面、进度、动画和音效 |
| 配置 | Assets/Resources | 食谱规则JSON与带资源引用的目录资产 |
| 工程工具 | Assets/Multiplayer/Editor | 校验、测试、Windows构建菜单 |

实际启动仍使用原 GameScene；场景加载后，在原脚本 Start 之前关闭单机逻辑和UI，避免两套系统同时生成物品与计时。只给原3个美术适配脚本补充了读取资源或设置显示的方法。原单机资产保留用于复用，不参与多人对局的状态裁决。

## 自动测试与最终验收

Unity中可以运行菜单 `Kitchen Chaos → Run Regression Tests`。测试覆盖纯C#服务端规则和本机真实TCP收发，结果写入Console。也可安装 .NET 8 SDK 后在工程最外层运行：

```powershell
dotnet run --project .\tests\Multiplayer.Tests.csproj
```

详细检查范围和待做的画面验收见 `验证记录.md`。协议字段与权威规则见 `联机协议.md`。不需要训练AI、申请API Key或启动外部评分服务。
